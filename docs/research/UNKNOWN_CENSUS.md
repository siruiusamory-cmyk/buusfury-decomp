## U2. Every instrument, per region, against its null

Each cell is `rows / bytes` the instrument fired on, then the same instrument on a seeded
byte permutation of each row. The null means two different things, and the instrument list
says which kind each column carries:

- statistics (`sample`, `tiles4`, `tiles8`): the null is the mean of the same statistic over 5 seeded
  permutations of the row, and a fire is the retail reading beating that mean by more than
  0.05; these are the only null-adjusted cells in the table;
- shape probes (the other seven): the null is the SAME boolean probe on ONE seeded
  permutation, i.e. the rate at which the shape occurs by chance. A probe fire is not gated
  on it, so the retail and null counts are two measurements of the probe, not a comparison.

A `0` in a probe's cell is not evidence of absence: every probe starts at the row's first
byte and stops at the row's end, so a container, table or codec that begins inside a row is
invisible to all of them, and the tile statistic fails its own positive control below.
A probe's non-detection is therefore the instrument's reach, not a measured absence (P-661).

The instruments, exactly as re-run:

- `sample`: the signed lag-1 Pearson coherence beats the row's own shuffle null by > 0.05 (assetdir_samples.correlation, the test BF-ASSETDIR-CODEC-001 ran on the known PCM)
- `webfoot`: a PACKED (kind 1/2) container starts at the row start and ends inside the row (raw_remainder.webfoot_extent, the census's own extent rule)
- `jcalg1`: the JCALG1 stream at the row start terminates inside the row (jcalg1.probe)
- `bios`: a BIOS LZ77/RLE/Huffman/diff block starts at the row start and fits inside it (bios_block_scan.decode)
- `tiles4`: the share of horizontally adjacent pixels that repeat, read as 4bpp 8x8 cells, is >= 0.60 and beats the row's own permutation by > 0.05. The control table below shows the measured graphics blocks do not reach the threshold, so this statistic fails its own positive control and a fire here is NOT graphics evidence
- `tiles8`: the same statistic read as 8bpp cells; it fails the same positive control
- `palette`: the row is whole halfwords, >= 8 of them, and EVERY halfword has bit 15 clear (a 15-bit BGR palette word)
- `pointers`: the wider density rule: >= 16 B, >= 8 grid words, >= 50 % of them ROM/IWRAM/EWRAM addresses
- `thumb`: a sequential ARMv4T Thumb decode covers >= 95 % of the row (raw_remainder.shape_coverage, recorded as non-discriminating)
- `text`: text_tables.classify names the row a text, record-table or numeric-constant class

## The sample-stream test: its controls, and why it is not the class predicate

Positive control: the 143 asset-directory blocks the policy sets as 8-bit signed sample data
kept as identity copies (K-234). 122 of 143 entries beat their own shuffle null by more than
0.05, mean lag-1 0.600 against a mean null of -0.002.

Applied to the `unknown` population the same rule fires on **546 rows / 321867 B**, against 565 rows
on the permuted copies. It is not specific to samples, which is why it is reported here and
not used as a class predicate: the same rule over every class of the census, under the
population's own 5-draw null, reads

The `unknown` row here is the population paragraph's own measurement: both use the
population's 5 draws, so both read the same fired rows. An earlier three-draw variant of this
table read 594; a draw count is part of the protocol, so only the 5-draw reading is quoted and
the table and the paragraph are one experiment, not two.

`text/tables` is a class the tree calls data tables and `graphics` one it calls pixels, so a
statistic that also fires on their bytes does not name samples. Both shares below use one
aggregation, the byte-weighted mean of each row's modal-byte share: the residual's bytes read
45.5 % against 8.0 % for the known sample blocks, which is the quantity this statistic
actually separates; the audio class therefore takes the record that names a block, not this
test.
