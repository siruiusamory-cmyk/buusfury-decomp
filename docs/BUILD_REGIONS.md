## Notes

### `rom_header` (0x000000-0x0000C0, 192 bytes)

GBA header: entry branch, the 156-byte mandated Nintendo logo, then title/game-code/checksum. The reference build regenerates it from source; we deliberately do NOT, because 156 of these 192 bytes are a fixed platform constant belonging to Nintendo. The 36 meaningful header bytes are instead verified independently by tools/buusfury/identity.py against config/rom.json, which is what actually detects a wrong revision. Promoting this region to class=generated is a DECOMP-ROM-MAP-001 item.

### `crt0` (0x0000C0-0x000158, 152 bytes)

C runtime start-up: CPU mode and stack setup, display/sound hardware init, then a tail branch to 0x0800419D. 0x98 bytes: 28 instructions plus a 7-word literal pool whose last entry (0x0800419D) ends exactly at 0x000158, so the first opaque range begins flush.

### `opaque_01` (0x000158-0x03D4D0, 250,744 bytes)

Largest single opaque range below the string pool. 250,744 bytes of engine code.

### `gbaram_text` (0x03D4D0-0x03D5B8, 232 bytes)

232 bytes of hand-transcribed Thumb. asm/GBARam.s line 5 preserves the command line that produced the original: 'tcpp -S -c -cpu ARM7TDMI -O1 src/GBARam.c', annotated 'For now, just assembly because of alignment issues.' This is the ONLY surviving evidence of the original compiler's optimisation level and the single most valuable input to DECOMP-COMPILER-PROBE-001.

### `opaque_02` (0x03D5B8-0x03D63C, 132 bytes)

132 bytes. GBARam_Malloc, left opaque even inside the GBARam.s area.

### `opaque_03` (0x03D63C-0x03D730, 244 bytes)

244 bytes. GBARam_Free, likewise left opaque.

### `gbaram_data` (0x03D730-0x03D740, 16 bytes)

16 bytes: four DCD values (0x02000800, 0x03003488, 0x0000FDFE, 0x7FFFFFFF) forming the GBARam allocator's local variables. Pure data with no toolchain dependency - trivially promotable to class=generated. Kept opaque for the baseline so that no ROM-derived bytes are committed.

### `opaque_04` (0x03D740-0x03D784, 68 bytes)

68 bytes, named by the reference project but not disassembled.

### `opaque_05` (0x03D784-0x049114, 47,504 bytes)

47,504 bytes.

### `afterlibs_thunk` (0x049114-0x049120, 12 bytes)

12 bytes: an ARM veneer. 'LDR r12,|FUN_08046aec_PTR|' / 'BX r12' / 'DCD 0x08046AED'. The odd target (0x08046AED) sets the Thumb bit. The reference project's name 'MaybeStart' records that even this thunk's role is not established.

### `opaque_06` (0x049120-0x055620, 50,432 bytes)

50,432 bytes.

### `asset_intro` (0x055620-0x0561C4, 2,980 bytes)

2,980 bytes. VERIFIED byte-identical when rebuilt from assets/intro.bmp. JCALG1 stream header: 01 00 00 00 then a u32 decompressed size of 0x9600 = 38,400 = exactly the 240x160 8bpp frame that grit produces.

### `dat_080561c4` (0x0561C4-0x05622C, 104 bytes)

104 bytes = 26 data words: runtime pointers, a Region_TitlescreenMenu rect, and four (destination, size=0x2000, pointer) triples for the corner blits. Address constants with no toolchain dependency; kept opaque for the baseline so no ROM-derived bytes are committed.

### `color_transforms` (0x05672C-0x05792C, 4,608 bytes)

4,608 bytes = 18 tables of 256 unsigned char: a screen-fade / colour-effect LUT bank (lut_fx_8bit, lut_fx_grayscale, lut_fx_dark0-2, red0-2, white0-5, green0-3). Placed by scatter.ld section COLOR_TRANSFORMATIONS 0x0805672c from color_transforms.o(.constdata). The reference compile command carries NO optimisation flag: 'armcpp -c src/color_transforms.cpp -o build/color_transforms.o', so the ADS 1.2 default applies - a DECOMP-COMPILER-PROBE-001 question.

### `strings` (0x05792C-0x06D4E0, 89,012 bytes)

89,012 bytes, the single largest non-opaque region and 1.06% of the ROM on its own. 1,534 wchar_t string literals (ADS wchar_t is 2 bytes, matching the UTF-16LE pool) followed by the pointer table, emitted as one C++ translation unit of ~3,071 lines. Names carry their own addresses (u_Start_0805792e), so the file is self-locating. Placed by scatter.ld section STRINGS 0x0805792c.

### `opaque_07` (0x06D4E0-0x071758, 17,016 bytes)

17,016 bytes. First range of the 'placeholder' area, which is otherwise entirely INCBIN.

### `asset_dialogbox` (0x071758-0x071A6C, 788 bytes)

788 bytes. VERIFIED byte-identical. The reference build passes 788 as an explicit minimum size, which is exactly the uncompressed stream's own length - an unusually strong self-check that this boundary is correct.

### `asset_dialogbox_small` (0x071A6C-0x071C90, 548 bytes)

548 bytes. VERIFIED byte-identical. The second JCALG1 stream header at 0x071A6C declares 0x2800 = 10,240 bytes, matching grit's output exactly.

### `opaque_08` (0x071C90-0x3BE3D4, 3,458,884 bytes)

3,458,884 bytes. The largest opaque range - 41.2% of the ROM on its own, and the bulk of the game.

### `asset_splash` (0x3BE3D4-0x3C33F8, 20,516 bytes)

20,516 bytes. VERIFIED byte-identical. The JCALG1 stream at 0x3BE3D4 declares 0x9600 = 38,400 bytes decompressed.

### `opaque_09` (0x3C33F8-0x7B89A8, 4,150,704 bytes)

4,150,704 bytes - 49.5% of the ROM. Together with opaque_08 this is 90.7% of the image in two INCBIN directives.

### `opaque_10` (0x7B89A8-0x800000, 292,440 bytes)

292,440 bytes labelled '<null bytes>' by the reference build. VERIFIED to be 0xFF-filled, not null. The label is wrong; the range is NOT proven unused. LOG1-REMAKE's TOOLKIT-011 measured 516 pointer-shaped little-endian u32 hits into this range and explicitly refused to promote it to free space. Do not treat it as free space without independent ownership evidence.
