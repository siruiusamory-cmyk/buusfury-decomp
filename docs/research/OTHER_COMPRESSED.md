# `other-compressed` row by row: the format, the round trip, and what the class really held

Generated by `tools/research/other_compressed.py` (GEN-COMPRESSED-001); the row set is the
census's own `other-compressed` class **at the 2026-10-16 master** (`docs/research/RAW_REMAINDER.csv`,

every run and asserted against the recorded tally.

## What the format is

- A **packed Webfoot/JCALG1 container**: `{u32 kind, u32 declared_size}` then the packed body
  at +8. `kind` 1 and 2 are the packed kinds, `kind` 0 is STORED - a plain copy
  (`tools/webfoot/webfoot_lz.py:140-144`); the header is read at `+0`/`+4`
  (`tools/webfoot/webfoot_lz.py:read_header`, `tools/research/bios_block_scan.py:jcalg1_container`).
- The body is the engine's own JCALG1 stream. Its decoder in this tree's source is
  `asm/rest_of_the_game.s:14391` `|sub_087b79e4|` (file `0x7B79E4`), with its bit reader at `:14556` and its end code at `:14575`;
  it is DMA-copied to IWRAM at boot (`asm/crt0.s:51` `hardware_conf_2 DCD 0x087B79A4`) and
  entered at `0x03000040`. The host port is `tools/research/jcalg1.py`; the independent
  reader is `tools/webfoot/webfoot_lz.py:unpack`.
- The encoders of this tree are `tools/compress/compress.exe` (JCALG1 r5.32, wrapped by
  `tools/compress/main.cpp`, which writes the kind-1 header and drops the checksum) and
  `tools/webfoot/webfoot_lz.py:pack`. They do NOT agree: measured on the 46 packed rows, the
  re-encode through `compress.exe` reproduces retail on 45 and differently on 1, and `pack`
  reproduces none of them (`kind 2` header, first differing byte 0, output never shorter).
  So the retail tokenization is `compress.exe`'s, and a row it does not reproduce needs an
  encoder this tree does not have.

## The finding: 25 of the 71 rows were never compressed data

The class predicate is `webfoot_lz.validate_retail_termination(rom, row_start)` succeeding with
its `packed_end` inside the row. That function requires the stream's own escape **only on the
packed path** - a `kind` 0 header is returned after a bounds check alone
(`tools/webfoot/webfoot_lz.py:511-520` returns before `_unpack_stream`) - so any row whose first
four bytes happen to be a small integer was accepted as a "container" ending at
`start + 8 + declared`. Measured: %d of the %d rows carry a `kind` 0 header (%d of them
declaring zero bytes), and 127 of the 4,322 census rows have a first word in 1..0x4000 that the
stored path would accept. `raw_remainder.webfoot_extent` now requires a PACKED kind, so those
rows fall to the class their own bytes support. That is a correction to the census instrument,
not to the bytes: no byte of any row moved.

## The promotion (SC2)

- The %d `packed-byte-exact` rows are the 45 slices of `asm/rawlabeled_3bbe70.s`
  (0x3BBE70..0x3BD2F8, 5,256 B, one container per slice). `tools/research/generate_jcalg1.py
  `--sweep-class other-compressed --apply` replaced each slice token with
  `INCBIN build\jcalg1\gen_<start>_<end>.bin`; the build re-encodes the stored decoded payload
  with `compress.exe` and refuses unless the result is the image's own bytes
  (`generate_jcalg1.encoded`).
- The `packed-differs` row stays INCBIN with its reason; the `stored-kind` rows were never
  candidates.
